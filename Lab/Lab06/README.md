## 实验内容

本实验将引导学员在 ARC Visualizer 中使用增量需求，为已有应用的编译结果添加新功能，并观察需求、画布和生成结果在增量编译过程中的变化。

### 实验材料

本实验延续 Lab04 的环境和操作方式。Lab06 目录额外提供了 [`ticket-booking-quickstart-fixed`](./ticket-booking-quickstart-fixed/)，其中包含本次增量编译所需的需求内容。

如果希望更快开始实验，也可以直接复用 Lab04 提供的 `demo_wo_ref`，并在此基础上完成本实验。

## 实验步骤

### 1. 打开需求编辑器

任选一个需求节点，单击左侧栏中的加号按钮，进入 `requirement editor` 界面。

![打开需求编辑器](./images/fig6-1.png)

### 2. 新增需求节点

在右上角打开 `More-Add Children/Sibling`，根据需要选择新增子节点或同级节点。

![使用 More-Add Children/Sibling 新增节点](./images/fig6-2.png)

例如，可以新增一个与“注册”同级的节点，并将其规划为“登录”功能。

![新增与注册同级的登录节点](./images/fig6-3.png)

### 3. 填写需求描述

填写新增需求的具体内容。一个完整、清晰的需求描述通常应包含：

- 标题；
- 依赖关系；
- 需求描述；
- 一个或多个 `scenarios`。

![填写需求描述](./images/fig6-4.png)

需求描述应尽量明确功能目标、依赖的已有需求以及需要满足的使用场景，便于后续生成接口、测试和实现。

### 4. 保存需求并运行增量编译

完成编辑后，单击右上角的 `Save` 返回主画布。画布会自动更新，确认新增或修改的需求节点已经显示后，执行 `Run`。

![保存需求并返回主画布](./images/fig6-5.png)

ARC Visualizer 会根据新增或修改后的需求，继续生成相应的接口、测试和实现。请观察编译过程及主画布中的节点变化。

![运行增量编译后的结果](./images/fig6-6.png)

### 5. 检查增量编译结果

运行完成后，检查以下内容：

- 新增需求是否出现在 Canvas 中；
- 是否生成了与新需求相关的接口和测试；
- 生成结果是否写入当前工作区；
- 新功能是否能够在 Preview 中启动和检查。

## 实验要点

- 增量编译应基于当前工作区和已有编译结果进行，不要误用其他实验的工作区。
- 新增需求时，应同时填写清晰的依赖关系和使用场景。
- 保存需求后再执行 `Run`，以确保 ARC Visualizer 读取到最新内容。
- 实验结束后，结合 Canvas、Traceability 和 Preview 检查需求到实现的完整链路。
