This lab demonstrates how to use ARC Visualizer to complete an end-to-end workflow from requirement input and application generation to result evaluation.

The basic loop of the lab is:

```text
Requirement
-> ARC Compile
-> Canvas / Traceability
-> Web App Preview
-> Validation Test Cases
-> Validation Results
```

ARC Visualizer is a VS Code extension. It organizes the ARC source directory, workspace output directory, Requirement input directory, and Validation test directory, and presents generated results and evaluation results together in Canvas, Traceability, Preview, and Validation Results.

## Lab Content

This lab contains a complete generation and evaluation workflow:

- Use the Requirement directory to provide the software requirements and reference materials to be implemented;
- Use ARC to run requirement compilation and application generation;
- View requirements, interfaces, tests, and their relationships in Canvas;
- View traceability relationships from requirements to generated results in Traceability;
- Start the generated application with Web App Preview and perform a manual inspection;
- Import external Validation Test Cases as strict validation independent of tests generated by ARC Agent;
- Run Validation using Playwright;
- View the pass status, title, duration, and overall pass rate of each test in Validation Results.

Validation does not replace tests generated by ARC Agent. It provides a set of external, relatively fixed acceptance tests to check whether the generated application satisfies predefined behavioral requirements.

At a minimum, record the following for each lab run:

- The Requirement input used;
- The ARC source directory and API configuration used;
- Whether the generation process completed;
- Whether the generated application could start;
- The total number of Validation tests, number passed, and pass rate;
- The requirement, code location, and logs associated with failed tests.

## Environment Setup

### Software Requirements

- VS Code
- Python 3.11+
- Node.js LTS
- npm
- Git

ARC compilation requires Python. Web App Preview and Validation require Node.js, npm, and the `backend` in the generated project.

### Install the Playwright Browser

Run the following command in a command-line terminal to install the Playwright browser environment:

```bash
npx playwright install
```

### Install the Extension

Search for and install `ARC Visualizer` in the VS Code Extensions view.

After installation, the following commands are available in the Command Palette:

- `ARC Visualizer: Select ARC Source Directory`
- `ARC Visualizer: Import Requirement Directory`
- `ARC Visualizer: Open Canvas`
- `ARC Visualizer: Run ARC Compile`
- `ARC Visualizer: Stop ARC Run`
- `ARC Visualizer: Open Web App Preview`
- `ARC Visualizer: Stop Web App Preview`
- `ARC Visualizer: Import Validation Test Cases`
- `ARC Visualizer: Run Validation Tests`
- `ARC Visualizer: Open Validation Results`

### Check the Environment

Confirm that the following commands can be run on your computer:

```bash
python --version
node --version
npm --version
git --version
```

On Linux or macOS, if your system uses `python3`, you can run:

```bash
python3 --version
```

## Running the Lab

### 1. Open the Lab Workspace

Open a workspace directory in VS Code that is prepared to receive generated results.

The workspace should correspond to this lab. Do not reuse old Preview or Validation results across multiple workspaces.

### 2. Select the ARC Source Directory

Run:

```text
ARC Visualizer: Select ARC Source Directory
```

Select the ARC source directory containing `main.py` and `requirements.txt`.

### 3. Configure the API

In VS Code Settings, fill in the API configuration used by ARC Visualizer, including:

- API Key;
- API Base URL;
- Model name;
- API mode;
- Any other model parameters that need to be synchronized with ARC.

Before running ARC, the extension synchronizes the relevant configuration to the `.env` file in the ARC source directory.

Do not commit real API credentials to the repository.

### 4. Import the Requirement

Run:

```text
ARC Visualizer: Import Requirement Directory
```

Select the Requirement directory used for this lab. After the import completes, confirm that the workspace contains:

```text
.arc/requirement/
```

### 5. Open Canvas

If Canvas is not already open, run:

```text
ARC Visualizer: Open Canvas
```

Canvas is the primary observation interface for this lab. It displays requirement nodes, interface nodes, test nodes, and the relationships among them.

### 6. Run ARC Generation

You can click `Run` in the Canvas toolbar or run:

```text
ARC Visualizer: Run ARC Compile
```

The extension starts ARC from the selected ARC source directory and reads `.arc/requirement` from the workspace. During compilation, ARC generates or updates the target project and its related results according to the requirements.

After generation completes, observe:

- Whether requirements and generated results appear in Canvas;
- Whether Traceability forms relationships from requirements to implementations, interfaces, and tests;
- Whether the `.arc` data in the workspace is updated;
- Whether the ARC run ends normally.

If you need to interrupt generation, run:

```text
ARC Visualizer: Stop ARC Run
```

### 7. Start Web App Preview

Run:

```text
ARC Visualizer: Open Web App Preview
```

The extension executes the following command in the `backend` directory associated with the current workspace:

```text
npm run start
```

After the backend starts, the extension opens the application page in VS Code's built-in Integrated Browser.

Preview opens in the editor group beside Canvas and does not replace the main Canvas page. You can use the built-in browser's refresh, forward, back, and address-bar functions to inspect the application.

Perform at least one manual inspection during the lab, for example:

- Whether the page loads normally;
- Whether key pages and entry points exist;
- Whether the main operations described in the requirements can be performed;
- Whether the page displays any obvious runtime errors.

To stop Preview manually, run:

```text
ARC Visualizer: Stop Web App Preview
```

When the Preview tab is closed, the extension also automatically stops the corresponding backend process.

### 8. Import Validation Test Cases

Run:

```text
ARC Visualizer: Import Validation Test Cases
```

Select the Validation directory containing the `.spec.ts` files. After the import, confirm that the files are located in:

```text
.arc/validation/
```

Validation tests should target observable behavior of the generated application and should not depend on temporary directories internal to the extension.

### 9. Run Validation

Run:

```text
ARC Visualizer: Run Validation Tests
```

For this evaluation, the extension performs the following process:

1. Temporarily copies `.arc/validation` to `backend/test-e2e/validation`;
2. Starts `npm run start` in the `backend` of the current workspace;
3. Runs Playwright tests for each `.spec.ts` file;
4. Extracts each test's status, task title, code location, and duration from the Playwright output;
5. Summarizes the number of tests passed and the pass rate;
6. Writes logs and structured results to `.arc/validation`;
7. Stops the backend used by this Validation run;
8. Deletes the temporary Validation files injected into the backend.

Running Validation should not modify persistent content that originally exists in the backend. After testing completes, the Validation files injected into the backend are removed.

### 10. View Validation Results

Run:

```text
ARC Visualizer: Open Validation Results
```

Validation Results opens an independent page beside Canvas and displays:

- `TESTS PASSED`;
- `Pass Rate`;
- The `PASSED` or `FAILED` status of each test;
- The test task title;
- The test duration.

Validation Results and Preview can share the editor group beside Canvas without occupying the main Canvas page.

## Output and Records

### ARC and Canvas Output

The main output is located in the `.arc` directory of the current workspace:

- `.arc/requirement/`
- `.arc/node_sessions/`
- `.arc/traceability/`
- `.arc/processing_queue.json`

Canvas and Traceability read this data and display the current generation state.

### Validation Output

After Validation completes, the main results are located at:

```text
.arc/validation/results.json
.arc/validation/summary.json
.arc/validation/logs/
```

These files and directories contain:

- `results.json` stores the structured result for each test item;
- `summary.json` stores the totals, number passed, number failed, pass rate, and log index for the run;
- `logs/` stores individual test logs and summary logs for each run.

The logs directory keeps at most the 5 most recent run records.

### Recommended Lab Records

For each lab run, record:

- Lab workspace path;
- ARC source directory version;
- Requirement input version;
- Validation input version;
- Model name and Base URL in the API configuration;
- Whether ARC generation succeeded;
- Manual Preview inspection results;
- Total Validation tests, number passed, and pass rate;
- Logs and code locations for failed tests.

## Interpreting the Results

The evaluation results should be considered together with three types of information:

1. **Generation process results**
   - Whether ARC completed;
   - Whether the generated results were written to the workspace;
   - Whether Canvas and Traceability formed the expected content.

2. **Manual run results**
   - Whether Preview started successfully;
   - Whether the application page could be operated;
   - Whether the key workflows behaved normally.

3. **Validation results**
   - Whether each external test passed;
   - What the overall pass rate was;
   - Which requirement was associated with each failed test;
   - Whether the failure location and logs support further diagnosis.

The pass rate reflects only the proportion of passing tests in the Validation test set and cannot by itself represent the quality of the complete application. The lab report should also record the specific behavior and logs for failed tests.

## Frequently Asked Questions

### Preview Cannot Start

Confirm that:

- The current workspace contains `backend/`;
- The backend contains a usable `package.json`;
- `npm run start` can be run independently in the backend directory;
- No old Preview process from another workspace is occupying the port;
- The current command is operating on the correct workspace.

### Validation Does Not Generate Results

Confirm that:

- The `.spec.ts` files have been imported;
- The current workspace contains `backend/`;
- The current run log was generated in `.arc/validation/logs/`;
- The backend can start normally;
- The VS Code extension window has been reloaded;
- The opened Validation Results belongs to the current workspace.

### Validation Results Do Not Match the Logs

Check the following first:

- Whether the current run used the latest compiled version of the extension;
- Whether every test in the log has its own entry;
- The generation times of `results.json` and `summary.json`;
- Whether `.arc/validation` from another workspace was read by mistake;
- Whether an old backend or Preview process still exists.

### Interrupt a Run

During an ARC generation run, execute:

```text
ARC Visualizer: Stop ARC Run
```

During a Preview run, execute:

```text
ARC Visualizer: Stop Web App Preview
```

Validation runs automatically manage the temporary backend and injected files.
